## A. 재료 수집 — datapack 만 읽고 쓰면 안 된다

datapack 은 출발점이지 재료의 전부가 아니다. 여덟 건 모두에서 **원문을 직접 열었고**,
그 과정에서 datapack 에 없거나 틀린 사실이 매번 나왔다.

### A-1. 반드시 읽는 것 (순서대로)

1. **`out/<종목폴더>/datapack.md` 전문.** 재무표(2절)에서 멈추지 말고 **8절 「공시 본문」을 끝까지** 읽는다.
   수주잔고·가동률·제품별 매출 비중·소송·제재가 거기 있다.
2. **프로젝트의 직전 보고서와 「추정전제_및_모니터링노트」** (`project_read`).
   노트의 「다음 분기에 재검증할 항목」이 이번 보고서의 **출발점**이다.
   **직전 추정이 맞았는지부터 확인하고, 그 결과를 본문에 쓴다.** 이게 이 시리즈의 신뢰도다.
3. `입력_리포트PDF/<종목명>/` 의 PDF. **파일명이 다른 회사면 쓰지 않는다** — 폴더에 잘못 들어온 파일이 실제로 있었다.
4. 원문 직접 조회 (A-2).
5. 웹 검색 (A-3).

### A-2. 원문을 직접 연다 — 이게 수동과 자동을 가르는 지점

**해외 종목 (MXL·RCMT·ETON·ACU·KFRC 에서 실제로 한 것)**

`WebFetch` 는 SEC 에 접속된다. **bash 의 curl 은 안 된다(exit 56).** 반드시 WebFetch 를 쓴다.

| 목적 | 주소 |
|---|---|
| 연간 시계열 (매출·영업손익·순손익·EPS·매출총이익) | `data.sec.gov/api/xbrl/companyconcept/CIK##########/us-gaap/<개념>.json` |
| 제출 목록 | `data.sec.gov/submissions/CIK##########.json` |
| 파일 목록 | `www.sec.gov/Archives/edgar/data/<cik>/<접수번호숫자만>/` |
| 주석별 표 (매출 세분화·집중도·우발채무·부채) | 같은 폴더의 `FilingSummary.xml` → 거기 적힌 `R##.htm` |
| 실적 보도자료 전문 (가이던스·GAAP 조정표) | 8-K 폴더의 `EX-99.1` (파일명은 대개 `...exhibit991.htm`) |

`www.sec.gov/cgi-bin/browse-edgar` 는 **차단**되어 있다. 쓰지 않는다.

**반드시 확보할 네 가지** (여기서 매번 결정적인 사실이 나왔다)

- **제품군·부문별 매출 세분화** → MXL 에서 「성장의 84%가 인프라 한 곳」이 여기서 나왔다
- **GAAP → non-GAAP 조정표 전 항목** → MXL 에서 「조정 영업이익의 88%가 주식보상」이 여기서 나왔다
- **고객·공급업체 집중도 주석** → MXL 의 「한 공급사가 재고 약정의 57%」가 여기서 나왔다
- **우발채무·소송 주석 본문**(요약 XBRL 말고 서술 원문) → MXL 의 실리콘모션 중재가 여기서 나왔다

**국내 종목** — DART 원문을 같은 밀도로 읽는다.

> **DART 문서 뷰어는 열리지 않는다** (2026-08-21 확인).
> `dart.fss.or.kr/dsaf001/main.do` 와 `/report/viewer.do` 는 robots.txt 로 자동 수집이 막혀 있고
> KIND(`kind.krx.co.kr`)는 403 을 준다. **이건 우회 대상이 아니라 그냥 못 여는 것이다.**
> 그래서 국내 종목의 1급 재료는 **datapack 8절에 수집기가 받아 둔 정기보고서 본문 원문**이다.
> 수집기가 DART OpenAPI 로 받아 온 원문 텍스트이므로 등급은 1급이 맞다.
> **8절을 끝까지 읽었으면 A 조건을 충족한 것으로 본다.** 다만 그 사실과, 8절이 글자 수 제한으로
> 잘려서 확인하지 못한 부분이 있으면 그것을 보고서 부록에 밝힌다.
> OpenDART 의 JSON API(`opendart.fss.or.kr/api/...`)와 회사 IR·보도자료는 WebFetch 로 열리므로
> 그쪽은 반드시 직접 확인한다.

- 사업보고서·분기보고서 **본문**: 「II. 사업의 내용」의 제품별 매출 비중·판매단가·원재료 단가·가동률·수주잔고
- **주요사항보고서**와 최근 공시 원문
- **DART 확정치가 증권사 추정치보다 우선한다.** 인바디에서 증권사 추정치를 확정치로 잘못 쓴 적이 있고,
  그 하나 때문에 VI절의 결론이 뒤집혔다. **숫자를 쓸 때마다 출처가 확정 공시인지 확인한다.**

### A-3. 웹 검색 — 세 가지는 반드시 따로 찾는다

1. **시장 규모와 성장률** — 1차 출처(정부·협회·조사기관)로. 그리고 **회사 성장률과 나란히 비교**한다.
   조사기관 수치가 회사 실제 매출과 앞뒤가 안 맞으면 **쓰지 않고, 안 맞는다는 사실을 본문에 밝힌다.**
   (ACU 에서 「글로벌 구급함 시장 2억 달러」가 회사 매출 1.3억 달러와 정합하지 않아 버렸다.)
2. **반대 의견** — `bear case` · `short thesis` · `overvalued` · `고평가` · `우려` 를 **검색어에 넣어 따로 찾는다.**
   이걸 안 하면 VII절이 회사가 써 준 리스크 요약으로 끝난다.
3. **컨퍼런스콜 전문** — 회사 IR 우선. 재게시본은 3급이므로 8-K·10-Q 로 대조한 뒤 쓴다.
   **애널리스트가 물었는데 경영진이 답을 피한 대목**을 찾는다. 그 자리가 대개 VII절의 핵심이다.
   (ETON 의 「제품별 매출 공개 거부」, MXL 의 「고객명 비공개」가 그렇게 나왔다.)

### A-4. 피어그룹은 매번 다시 고른다

config.yaml 에 적힌 피어를 그대로 쓰지 않는다. **사업 내용이 바뀌었으면 비교 대상도 바뀐다.**
MXL 은 매출의 절반이 AI 데이터센터로 옮겨 갔으므로 기존 피어(스카이웍스·코보 = 휴대폰 아날로그)를
버리고 아스테라랩스·크레도·마벨·셈테크로 바꿨다. **바꿨으면 왜 바꿨는지 본문에 한 문단 쓴다.**

> **[통과 조건 A]** 1급 재료를 최소 3건 확인했다 ·
> bear case 를 별도 검색어로 찾았다(찾아도 없으면 「없다」는 사실 자체를 리스크로 적었다) ·

### D-1. 파이썬 재검산 스크립트를 따로 쓴다

본문에 쓴 **모든 파생 수치**(증가율·비율·배수·합계·시나리오 함의가)를 원본 값으로 다시 계산해
본문 값과 대조하는 스크립트를 작성하고 실행한다. MXL 은 59항목이었다. 형식은 이렇다.

```python
def chk(name, 보고서값, 계산값, tol=0.05):
    d = abs(보고서값 - 계산값)
    good = d <= tol * max(abs(계산값), 1e-9)
    print(("  ✔" if good else "  ✗ 불일치") + f" {name}: 보고서 {보고서값} / 계산 {계산값:.4g}")
    return good
```

**하나라도 ✗ 면 본문을 고치고 다시 돌린다.** 스크립트를 고쳐서 통과시키지 않는다.

### D-2. 문체 점검 (2026-09-18 — 「산문 습니다체」 추가, 14항목)


**14항목 전부 ✔ 가 될 때까지 고친다.** PDF 변환은 그 뒤에 한다.

**2026-09-18 — 「산문 습니다체 95% 이상」이 들어갔다.** 사용자 지시로 산문 본문이
습니다체로 바뀌었다(`문체_가이드.md` §8·§9). 불릿은 음슴체 그대로다.
종결 다양성과 「같은 맺음 3연속」은 **종결어미를 뗀 어간**으로 센다 — 안 그러면
습니다체 글이 전부 「…니다」라서 다양성이 0에 가깝게 나온다.

**2026-09-02 — 어미를 재는 두 항목(평서형 비율·불릿 음슴체 비율)을 폐지했다.**
어미를 비율로 강제하니 문장이 내용이 아니라 비율을 맞추러 갔고, 그 결과가 「부자연스럽다」는 지적이었다.
두 값은 참고로 출력되지만 **판정에 들어가지 않는다.** 그 자리에 **「같은 맺음 3연속 8% 이하」**가 들어갔다 —
무엇으로 끝내라가 아니라 **같은 것으로 연달아 끝내지 마라**만 본다. 자세한 것은 `문체_가이드.md` §8.

**소제목은 질문형이 아니라 결론을 박은 명제형으로 쓴다.** 이건 어미 규칙이 아니라 가독성 규칙이라 그대로다.

그 다음으로 자주 걸리는 것은 「연결어로 시작 40% 이상」이며, 문단의 둘째 문장부터
앞을 받는 말(그런데·다만·이는·실제로·여기서·그 결과)로 시작하면 대개 해결된다(§7).

### D-3. PDF 를 눈으로 본다

```
pdftoppm -png -r 68 -f 1 -l 2 <보고서.pdf> /tmp/chk
```
로 렌더해 **Read 로 연다.** 표지와 본문 한두 쪽을 본다.
글자 깨짐·표 잘림·빈 페이지·사실 오류(연도·회사명)를 여기서 잡는다.

### D-4. 재료에 없는 숫자가 들어갔는지 확인

본문의 숫자를 훑으며 출처를 댈 수 있는지 본다. 못 대면 지우고 「확인되지 않는다」로 바꾼다.

## E. 산출물

한 종목당 네 개다.

1. `<회사명>_<코드>_기업분석보고서_YYYY.MM.DD.html` (차트 SVG 인라인)
2. 같은 이름 `.pdf` — `python3 make_pdf.py <html>`
3. **`이미지/` 폴더 — `python3 make_images.py <pdf>`**
4. `<회사명>_<코드>_추정전제_및_모니터링노트.md`

> **2026-08-23 변경 — DOCX 를 이미지로 바꿨다.**
> Jun 님이 결과물을 블로그에 올리는데 「워드보다 이미지가 올리기 쉽다」고 했다.
> `make_docx.py` 는 지워지지 않았으니 워드가 필요하면 따로 요청하면 된다.
> `make_images.py` 는 낱장 PNG(150dpi, 쪽당 1240×1754px)와 2단 전체본을 함께 만든다.
> **세로로 길게 이어 붙이지 않는다** — 한 줄로 붙이면 14쪽이 25,000px 가 되고 업로드가 거부된다.

**노트에 반드시 들어갈 다섯 가지**

1. 핵심 논지 (첫째·둘째·셋째, 각 한 문단)
2. **확인한 사실 표** — 항목 / 값 / 출처 / 등급(1급·2급). 그리고 **공개되지 않아 추정에 의존한 것**을 따로 적는다
3. 시나리오 전제 표 — 매출 / 전제 / 적용 배수 / 배수의 근거 / 함의 주가 / 확률, 그리고 확률가중값
4. **다음 분기에 재검증할 항목** — 각각 「무엇을 · 어디서 · 언제」. **무엇을 보면 이 보고서가 틀렸다고 판단할 수 있는지**를 구체적으로
5. **레드팀 관점에서 이 보고서 자체의 약점** — 어느 쪽으로 틀릴 수 있는지 양방향으로

저장 위치
- 맥: `out/<종목폴더>/` 에 네 개 모두
- 프로젝트: 보고서는 **차트 SVG 를 벗겨 낸 경량본**(450KB → 50KB)으로 `claude/<파일명>.html`,
  노트는 `claude/<회사명>_<코드>_추정전제_및_모니터링노트.md`
