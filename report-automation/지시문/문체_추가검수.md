# 보고서 문장·구성 추가 검수 — im-not-ai 적용

사용자가 2026-09-14 지정한 https://github.com/epoko77-ai/im-not-ai 의 규칙을
기업분석 보고서의 최종 문체 검수에 적용한다. 사실 검증 이후, 게시 승인 이전에 수행한다.

## 읽을 규칙

- `지시문/참고/im-not-ai/quick-rules.md`: A~J 패턴과 문맥별 탐지 기준
- `지시문/참고/im-not-ai/humanize-monolith.md`: 탐지 → 국소 윤문 → 원문 대조 원칙
- `지시문/참고/im-not-ai/SOURCE.md`: 고정 판본과 라이선스

원문 중 운영 방식·모델·작업 공간·출력 형식은 참고하지 않는다. 기존 보고서 HTML/PDF,
Codex JSON 판정, Claude 수정 인계 방식을 유지한다. 외부 도구 설치나 추가 에이전트 호출은 필요 없다.

## Codex가 검수할 것

1. 전문과 요약을 각각 읽고, 문장뿐 아니라 문서 전체에서 반복되는 구문·문단 전개를 확인한다.
   번역투, 반복 대구, 형식명사로 끝나는 문장, 기계적인 열거, 의의 과장, 추상 비유,
   문단마다 되풀이되는 도입·결산, 균일한 종결과 접속사를 규칙 ID와 실제 위치로 식별한다.
2. 자연스러운 글은 그대로 둔다. 특정 단어나 횟수만으로 일괄 치환하지 않는다.
   전문 용어·보고서 절 제목·비교표·위험 목록·실제 논리 구분에 필요한 열거는 보존한다.
   기존 공통 기준과 원문의 숫자 문턱은 탐지 보조로 사용하고, 의미 보존과 문맥 판단을 우선한다.
3. 부자연스러운 구간이 있으면 findings에 `[문체][규칙 ID] 위치 / 문제 구문 /
   의미를 유지하는 수정 방향 / 완료 기준`을 쓴다. 대표 예문을 제안할 수 있다.
   문서 전체에 같은 문제가 반복되면 대표 위치와 전수 점검할 범위를 함께 지정한다.
4. 의미 왜곡이나 이해를 실질적으로 방해하는 필수 문체 결함이 남았으면 `checks.writing=false`, `decision=revise`로 반환한다.
   동의어·어미·선호 문체 같은 선택적 개선만 남으면 writing=true를 유지하고 optional로 기록한다.
   검수를 실제 수행했고 수정할 결함이 없거나 수정본을 확인한 경우에만 writing=true다.
   사실 오류가 있어도 가능한 문체 검사를 이번 회차에 수행한다. 실제 수행 불가라면 false와 구체적인 제한을 기록한다.
5. 승인 판정의 reason에는 문체 추가 검수 수행 여부와 결과를 명시하고,
   sources에는 읽은 규칙의 로컬 경로·고정 커밋·확인 범위를 기록한다.
   형식 점검기 통과나 Claude의 자기평가만으로 자연스러운 글이라고 승인하지 않는다.

## Claude가 수정할 것

1. 사실·계산 수정 작업을 마친 판본을 백업한 뒤 문체만 다듬는다. 두 단계의 변경을 구분해 기록한다.
2. 규칙으로 식별한 구간만 국소 수정한다. 문장과 문단의 연결·어순·군더더기를 고치되
   보고서를 에세이·블로그체로 바꾸거나 문서 구조를 통째로 다시 쓰지 않는다.
3. 숫자·단위·날짜·종목명·핵심 개념·인용·각주·출처 URL·부정·비교 대상·인과관계·조건을 보존한다.
   특히 전망·가정·경영진 주장·확정 사실의 구분과 확신도를 그대로 둔다.
   `가능성이 있다`를 `발생한다`로, `확인이 필요하다`를 `확인됐다`로 바꾸지 않는다.
   해석이 불분명하면 원문을 보존하고 미해결 사유를 기록한다.
4. 원문에 없던 비유·감정·권위 있는 평가·새로운 근거를 넣지 않는다. 내용을 줄여 매끈하게 만드는 것도 금지한다.
5. 전문과 요약 모두 대조하고 HTML 변경 후 PDF를 다시 생성하여 표시를 점검한다.
6. 같은 인계의 `Claude 반영 내역 > 문체 추가 검수`에 규칙 판본, 범위, 규칙 ID,
   대표 변경 전후, 의미 보존 대조 결과, 남긴 표현과 이유를 적고 `재검토대기`로 인계한다.
   이미 자연스러워 변경하지 않았어도 확인 범위와 무변경 사유를 기록한다.

## 과도한 윤문 방지

원문 규칙의 변경률 30% 경고·50% 중단 원칙을 적용하되,
문체 단계 직전/직후의 표시되는 본문 텍스트끼리 코드로 비교한 경우만 수치를 보고한다.
HTML 태그·CSS·표 서식 변경이나 앞 단계의 사실 정정을 섞어 계산하지 않는다.
계산하지 않은 변경률을 추정해 통과로 쓰지 않는다. 광범위한 수정이 필요하면
작은 단위로 나누어 대조하고, 의미 보존을 확신하지 못한 변경은 되돌린다.
변경률이 낮아도 내용 보존 검증을 대신하지 못한다.
