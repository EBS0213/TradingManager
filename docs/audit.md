# 2026-11-08 코드 구조·설치·기능 검토

## 검토 범위와 한계

원본 추적 파일 905개를 기준으로 구성 요소를 분류했다. 전체 파일 목록과 정적 import, API 라우트, Python 구문 검사를 수행하고, 설치/실행·설정·DB·캐시·메뉴 전환·수집기 경로를 집중 검토했다. 기존 기능별 테스트도 실행했다. 모든 소스 줄의 의미를 사람이 개별 검토했거나 모든 외부 데이터 공급자를 실시간 시험했다는 의미는 아니다. 현재 수정은 기존 동작을 보존하는 데 초점을 맞췄으며, 전면 재작성이나 추정 성능 개선률을 주장하지 않는다.

## 기능별 검토

- 시장·주식: 완료 일봉 경계, 통화/종목 식별, 이전 자료 표시, 주요주식과 스크리너 구분을 기존 테스트로 확인. 목록 다운로드 중복과 캐시 저장 충돌을 수정했다.
- 경제·뉴스: 경제 캐시의 인스턴스 간 갱신 임대와 실패 재시도 제한은 유지했다. 뉴스 화면의 불필요한 경제 조회를 제거했다. 외부 서비스의 가용성과 제공 지연은 앱 속도와 별개다.
- 기록·관심종목: 서로 다른 필드의 동시 저장은 PostgreSQL JSON 병합으로 처리하는 기존 구조를 확인했다. 같은 필드의 다중 창 편집 충돌 처리는 향후 별도 개선 후보이며, 이번에 사용자 기록을 덮어쓰는 테스트는 하지 않았다.
- 차트게임: 미래 시세 편집으로 판단 시점의 진단이 바뀌지 않는지, 기간 경계·진행 저장·점수 재계산을 회귀 검사했다. 계산 규칙을 성능 명목으로 변경하지 않았다.
- 챗봇: 큐 임대·중복 실행 잠금과 오프라인 대기를 확인했다. 설정 주소 통일을 적용했다. Ollama 모델 자체의 답변 품질·속도 최적화는 별도 측정이 필요하다.
- 항공·해상: 공급자 상태, 재연결, 체크포인트, 배치 크기와 관측 시각 관련 기존 검사를 실행했다. ws 설치 누락과 업로드 주소를 수정했다. 실제 AIS 키로 장시간 연결하지 않았다.
- 리서치·보고서: 일반 게시판 화면과 보고서 저장 기반을 분리했다. 보고서 도구의 주소 중복을 수정했고 오프라인 상태·재시도·첨부 검사 56개를 실행했다. 실제 게시·메시지 발송은 하지 않았다.
- 스크리너: 규칙·공급자·예약 작업 구성을 확인하고 전체 Python 구문 검사를 수행했다. `rules.py`의 큰 규칙 집합은 향후 모듈 분리 후보지만 투자 판단 결과를 바꾸지 않도록 특성 테스트를 먼저 늘리는 것이 필요하다.

## 남은 검증·개선 후보

- 완전히 새 macOS 사용자/기기에서 Homebrew·Apple 개발 도구 설치까지 끝까지 확인.
- 실제 Windows 기기/CI에서 설치·중단 후 재개·시작/종료 검증. Mac에서 실행한 플랫폼 공통 단위 테스트만으로 대체하지 않는다.
- API 입력 크기/오류 코드 정책 통일, 기록의 같은 필드 충돌 검출, 오래된 캐시의 저장 용량 상한.
- 큰 스크리너 규칙 및 남아 있는 legacy HTML을 행동 보존 테스트를 확보한 뒤 분리.
- 다수 파일의 과거 서비스 운영 주석/문서 정리. 코드 동작과 문서 이력을 혼동하지 않도록 후속 작업으로 구분.
